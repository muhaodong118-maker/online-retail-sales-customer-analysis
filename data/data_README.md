# Data Directory说明

本目录用于存放本项目的原始输入数据及数据来源说明。为保持项目可复现，原始数据不应在这里被直接覆盖；清洗、转换和分析结果应由 `src/` 中的代码生成，并保存到 `outputs/`。

## 1. 数据集信息

- **数据集名称：** Online Retail
- **数据来源：** UCI Machine Learning Repository
- **官方页面：** https://archive.ics.uci.edu/dataset/352/online+retail
- **业务背景：** 英国一家线上零售商的交易记录。
- **数据时间范围：** 2010-12-01 至 2011-12-09。
- **原始记录数：** 541,909 条。
- **原始文件名：** `Online Retail.xlsx`

> 本项目使用的是历史交易数据，结果仅描述该数据集覆盖期间的情况，不能直接代表当前电商市场。

## 2. 下载与放置方式

1. 打开上方 UCI 官方页面并下载数据集。
2. 将原始 Excel 文件放在本目录，文件名保留为 `Online Retail.xlsx`。
3. 不要手动改写原始数据；如需更改清洗规则，请修改 `src/` 中的分析脚本并重新运行。

预期目录结构：

```text
data/
├── README.md
└── Online Retail.xlsx   # 本地原始数据文件；默认不提交到 GitHub
```

如果项目代码使用了不同的文件名或路径，请以代码中的实际配置为准，并同步更新本说明。

## 3. 字段说明

| 字段 | 含义 | 处理提示 |
|---|---|---|
| `InvoiceNo` | 发票/订单编号 | 以 `C` 开头的编号表示取消交易；需根据项目清洗规则判断是否纳入销售额分析。 |
| `StockCode` | 商品代码 | 一个商品可能以代码作为主要识别字段。 |
| `Description` | 商品描述 | 可能存在缺失值或描述差异，分析前需检查。 |
| `Quantity` | 本次交易的商品数量 | 可能出现负数，不能在未检查的情况下直接将其当作正常销量。 |
| `InvoiceDate` | 交易日期与时间 | 需解析为日期时间类型，并据此进行月度聚合。 |
| `UnitPrice` | 商品单价（英镑） | 需检查零值或异常值；销售额计算口径应与分析代码保持一致。 |
| `CustomerID` | 客户编号 | 部分交易缺少客户编号，因此客户分析基于可识别客户；须说明相应分母。 |
| `Country` | 客户所在国家/地区 | 可用于国家或市场维度的汇总分析。 |

## 4. 项目中的衍生字段与指标

原始数据不一定直接包含以下字段；它们应由项目代码计算生成：

- **Revenue（销售额）：** 通常根据 `Quantity × UnitPrice` 计算。是否纳入取消交易、退货或异常记录，必须以 `src/` 中实际实现的过滤规则为准。
- **Order Count（订单数）：** 按定义采用去重后的 `InvoiceNo` 统计；请在 SQL 中保持同一口径。
- **AOV（平均订单金额）：** 销售额除以订单数。销售额范围与订单数范围必须一致。
- **RFM 指标：** 使用客户最近购买时间（Recency）、订单频次（Frequency）和累计销售额（Monetary）构建。需在 README 或分析报告中说明快照日期、频次口径与金额口径。

## 5. 数据质量与分析注意事项

- 检查缺失值、重复记录、取消订单、负数量、零/异常单价及无效日期。
- 2011 年 12 月的数据只到 **2011-12-09**，属于不完整月份。月度趋势中应明确标注，不宜与完整月份直接作同等比较。
- 部分记录没有 `CustomerID`。客户数、复购比例和客户销售额占比需明确以“可识别客户”为分母，不能与全量销售额占比混用。
- 数据不提供商品成本，因此可以分析销售额和销量，但不能直接据此计算利润或毛利率。
- 商品分析时如排除 `DOT`、`POST`、`M` 等邮费/手工项目，应先排除再重新排名；不能直接从原始 Top 10 中删除后仍称为“过滤后 Top 10”。请确保过滤规则在 SQL、图表和报告中一致。
- 本项目输出的业务建议属于基于历史数据的分析假设；未经实验或额外数据验证，不应表述为已实现的收入提升或成本下降。

## 6. 数据与 Git 管理约定

默认不将原始 Excel 数据、个人虚拟环境、临时数据库或完整客户级明细提交到公开仓库。建议在 GitHub 仓库中提交本说明、处理代码、SQL 脚本、图表及经核验的汇总结果，并让使用者从官方来源下载原始数据。

请确认 `.gitignore` 至少覆盖相应的本地数据与临时文件，例如：

```gitignore
data/*.xlsx
*.db
.venv/
__pycache__/
```

如果项目确实需要共享可复现的派生数据，应先确认其必要性，并优先共享不包含客户级明细的聚合结果。
